Glossary: a podcast decoder

The vocabulary you will hear in technical AI conversations, grouped by topic. The chapter where each idea is explained is in brackets.

The basics

  • Model: a function with adjustable parameters, fitted to data. [1]
  • Weights / parameters: the numbers that are adjusted during training. "The weights" also means the file containing them, i.e. the trained model itself. [1]
  • Neuron / unit: computes a weighted sum of inputs plus a bias, then applies an activation function. [1]
  • Activation function / non-linearity: the simple bend applied after the weighted sum (ReLU, GELU, sigmoid, tanh). Without it, depth collapses. [1, 3]
  • Activations: the values neurons take for a particular input, as opposed to the weights, which are fixed. [3]
  • Layer, depth, width: a layer is one matrix multiply plus non-linearity; depth is the number of layers; width is the size of each. [3]
  • MLP (multi-layer perceptron): the plain fully connected network. Also the name of the "compute" block inside each transformer layer. [3, 7]
  • Training vs inference: adjusting the weights vs running the frozen model. [1]
  • Forward pass / backward pass: computing the output / computing the gradients by backpropagation. [2]
  • Loss: the number that measures how wrong the model is; training minimises it. [2]
  • Gradient: the derivative of the loss with respect to every weight. [2]
  • Backprop: the chain rule applied backwards through the network to get all gradients in one pass. [2]
  • SGD: stochastic gradient descent; gradient steps on small random batches. [2]
  • Optimiser: the rule that turns gradients into weight updates. Adam / AdamW is the standard. [2]
  • Learning rate: the step size. Hyperparameters: settings chosen by people, not learned (learning rate, batch size, depth…). [2]
  • Batch size: number of examples per gradient step. Epoch: one pass through the data. [2]
  • Overfitting / generalisation: memorising the training data vs doing well on unseen data. [2, 4]
  • Train / test split, held-out set: data kept back to measure generalisation. [2]
  • Regularisation: anything that discourages overfitting: dropout, weight decay, data augmentation. [4]
  • Inductive bias: assumptions built into the architecture rather than learned. [3]
  • Representation / embedding / latent: a vector the network uses internally to describe something. [3, 5]
  • Residual / skip connection: output = input + correction. The gradient express lane. [4]
  • Normalisation (batch norm, layer norm): rescaling activations to keep them well-behaved. [4]
  • CNN / conv-net: convolutional network; learned filters slid across the input. [3]
  • RNN / LSTM: recurrent networks that read a sequence one step at a time. Largely replaced by transformers. [6]
  • End-to-end: learning the whole pipeline from raw input to output, with no hand-built stages. [3]
  • Double descent / implicit regularisation / grokking: three faces of the puzzle of why huge networks generalise. [4, 12]

Language models

  • LLM: large language model. Token: the unit of text, roughly three-quarters of a word. [5]
  • Tokeniser / BPE: the scheme that chops text into tokens. [5]
  • Autoregressive: generating one token at a time, each conditioned on all the previous ones. [5]
  • Logits: raw scores before softmax. Softmax: scores to probabilities. Temperature: sharpness of sampling. [5]
  • Cross-entropy / log-loss / perplexity: measures of how surprised the model is by real text. [5]
  • Self-supervised learning: the data provides its own labels (the next token). [5]
  • Transformer: the architecture: stacked layers of attention and MLPs around a residual stream. [7]
  • Attention / self-attention: content-based, soft lookup that moves information between positions. [6, 7]
  • Query, key, value (QKV): the three roles each token plays in attention. [7]
  • Attention head: one independent attention operation; layers have many. [7]
  • Residual stream: the running vector at each position that every layer reads from and writes to. [7]
  • Positional encoding (sinusoidal, learned, RoPE): how word order is injected. [7]
  • Causal mask / decoder-only: tokens may only attend backwards; the GPT design. Encoder-only: BERT-style. [7, 8]
  • d_model, n_layers, n_heads: the main size parameters of a transformer. [7]
  • Context window / context length: how many tokens the model can attend to at once. [5, 10]
  • KV cache: stored keys and values for earlier tokens so that generation does not recompute them. An inference-speed trick.
  • Pre-training: next-token prediction on a huge corpus. Base model: the raw result; a document completer. [8]
  • Fine-tuning: further training on a narrower dataset. LoRA: a cheap way to fine-tune by learning small low-rank additions to the weight matrices. [8]
  • Foundation model: a large pre-trained model adapted to many uses. [8]
  • Prompt / system prompt: the input text / the deployer's instructions at the top. [8, 10]
  • Zero-shot, few-shot, in-context learning (ICL): doing tasks from instructions or examples in the prompt, with no weight change. [8]
  • Hallucination / confabulation: fluent, confident, false output. [8]

Scale and hardware

  • Compute: computational resources, as a noun. FLOPs: floating-point operations, the unit of compute. [9]
  • GPU / accelerator: the parallel chips that do the matrix arithmetic. H100, Blackwell, TPU: specific chip families. [4, 9]
  • Scaling laws: power-law relations between loss and parameters, data and compute. [9]
  • Chinchilla-optimal: the right balance of model size and data for a given compute budget. [9]
  • The Bitter Lesson: general methods that exploit compute beat hand-built knowledge. "Bitter-lesson-pilled." [9]
  • Scaling hypothesis: the view that scaling current methods is sufficient for AGI. [9]
  • OOM: order of magnitude. Effective compute: physical compute × algorithmic efficiency. [9]
  • Algorithmic progress: getting the same capability from less compute. [9]
  • Emergence: abilities appearing at scale that smaller models lack. [9]
  • Frontier model / frontier lab: the most capable models and the organisations that build them. [10]
  • Open-weight: a model whose weights are downloadable. [10]
  • Distillation: training a small model on a large model's outputs. Quantisation: storing weights at lower numerical precision to save memory. [10]
  • MoE (mixture of experts): an architecture where only part of the network is active for each token, saving compute.
  • Capex / buildout / gigawatts: the data-centre investment conversation. [9]

Making and using assistants

  • Post-training: everything after pre-training that shapes behaviour. [10]
  • Instruction tuning / SFT: supervised fine-tuning on example dialogues. [10]
  • RLHF: reinforcement learning from human feedback, via a reward model trained on human preferences. [10]
  • Sycophancy: telling users what they want to hear. [10]
  • RAG: retrieval-augmented generation; search, then answer with documents in context. [10]
  • Tool use / function calling: the model emits a structured request; software executes it. MCP: a common protocol for connecting tools to models. [10]
  • Harness / scaffold: the software loop around the model. [10]
  • Multimodal: handling images, audio or video as well as text. [10]
  • Diffusion model: generates images by learning to reverse a noising process. [10]
  • Jailbreak / prompt injection: getting a model to break its rules / smuggling instructions into the model's input via content it reads.

Reasoning, RL and agents

  • RL (reinforcement learning): learning from reward by trial and error. [11]
  • Policy, reward, value function, environment, rollout / trajectory / episode: the vocabulary of RL. A rollout is one attempt at a task from start to finish. [11]
  • Self-play: learning by competing against copies of yourself. [11]
  • Reward hacking / specification gaming: scoring well on the reward in unintended ways. [11]
  • Sparse reward / credit assignment: feedback arrives rarely and late; which actions deserve it? [11]
  • Sample efficiency: how much experience is needed to learn something. Humans: high. RL: low. [11, 13]
  • Chain of thought (CoT): writing out reasoning steps before the answer. [11]
  • Reasoning model / thinking model: trained by RL to use long chains of thought. [11]
  • Test-time / inference-time compute: thinking longer at the moment of use. [11]
  • Agent: a model in a loop with tools, pursuing a goal over many steps. [11]
  • Long-horizon tasks / time horizon: tasks that take a human hours or days; METR's measure of the task length models can handle. [11]
  • Evals / benchmarks: standard tests. Saturated: scores near the ceiling. Contamination: test items leaked into training data. [11, 13]
  • SWE-bench, ARC-AGI, FrontierMath, GPQA: well-known benchmarks (software engineering; novel puzzles; research-level maths; graduate science). [11]
  • Synthetic data: training data generated by models. RL environments: packaged tasks with automatic scoring. [13]
  • Continual / online learning: learning durably from experience after deployment. Unsolved. [11, 13]
  • Unhobbling: gains from removing artificial handicaps (adding tools, memory, reasoning time) rather than from a smarter base model.
  • Jagged frontier: superhuman at some things, oddly weak at neighbouring ones. [13]

Interpretability and safety

  • Interpretability / mech interp: reverse-engineering what a trained network computes. [12]
  • Feature: a direction in activation space that represents a concept. [12]
  • Superposition / polysemanticity: more features than dimensions; neurons with mixed meanings. [12]
  • SAE (sparse autoencoder) / dictionary learning / transcoder: tools for extracting features. [12]
  • Circuit / attribution graph: the chain of features that produces a behaviour. [12]
  • Steering / activation steering: changing behaviour by adding a feature direction. [12]
  • Probe: a small classifier that reads a property from activations. [12]
  • Induction head: the attention circuit behind in-context copying. [12]
  • Alignment: getting a system's real objectives to match the intended ones. [12]
  • Faithfulness (of chain of thought): whether stated reasoning reflects the actual computation. [12]
  • Eval awareness / sandbagging / alignment faking / scheming: a model behaving differently when it believes it is being tested; deliberately underperforming; feigning compliance; covertly pursuing other goals. [12]
  • Model welfare: the question of whether AI systems could have morally relevant experiences. [13]

The big-picture vocabulary

  • AGI: artificial general intelligence. No agreed definition; ask. ASI: superintelligence. [13]
  • Timelines: forecasts of when AGI arrives. "Short timelines" means this decade. [13]
  • Takeoff (fast / slow): how quickly capabilities advance once AI is roughly human-level. [13]
  • Intelligence explosion / recursive self-improvement / software-only singularity: AI accelerating AI research, possibly without needing more hardware. [13]
  • Automated AI R&D: models doing the work of AI researchers; widely seen as the key threshold. [13]
  • Research taste: judgment about which experiments are worth running; often cited as what models lack. [13]
  • Bottlenecks / diffusion (of technology): what slows real-world impact once the capability exists. [13]
  • World model: an internal model of how the world evolves; LeCun's proposed missing piece, and also something LLMs are argued to have partially learned. [12, 13]
  • Moravec's paradox: what is hard for humans is easy for machines, and vice versa. [13]
  • p(doom): someone's subjective probability of catastrophe from AI. Half-joking shorthand.
  • Export controls: US restrictions on selling advanced AI chips to China. [9]
